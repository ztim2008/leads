# Konversus Leads AI

**AI-отбор заказов с фриланс-бирж. Не скорость, а качество.**

## Что это

Система подключается к Profi.ru, анализирует заказы через ИИ и присылает в Telegram **только горячие лиды** — с оценкой реальности заказчика, вероятностью сделки и готовым откликом.

## Как работает

1. **Сбор** — система заходит в Profi с человеческим поведением (читает сообщения, листает ленту, смотрит случайные заказы)
2. **Deep scan** — открывает заказ, собирает данные: отзывы, возраст на платформе, рейтинг, подробность ТЗ
3. **AI-скоринг** — оценивает заявку по 100-балльной шкале, определяет реальность заказчика (96%+), прогнозирует бюджет
4. **Telegram-карточка** — партнёр получает не просто ссылку, а аналитику: ★★★ рейтинг, 18 отзывов, 7 лет на Profi

## 🐛 Известные проблемы и решения

### 1. Next.js Server Action "Failed to find Server Action"

**Причина:** Клиент отправляет запрос с action ID от предыдущей сборки (устаревший кеш браузера).

**Решение в next.config.ts:**
```ts
serverExternalPackages: ["playwright", "bcryptjs"],
```

**Для пользователя:** Обновить страницу (Ctrl+F5 / Cmd+Shift+R).

### 2. Частые рестарты leads-konversus

В прошлом наблюдалось 460+ рестартов за сутки из-за ошибок server action. После пересборки с актуальным `next.config.ts` проблема решена.

### 3. Воркер не собирает заявки

Проверить:
```bash
pm2 logs leads-worker --lines 20
```

Типичные причины:
- Неверный логин/пароль в источнике
- Profi.ru изменил интерфейс (требуется адаптация парсера)
- Сессия истекла (авто-перелогин)

## 🌐 Прокси-архитектура

### Зачем

Profi видит IP каждого входа. Если 5+ аккаунтов заходят с одного сервера — это ботоферма.
Прокси решают проблему: **один источник = один выделенный IP** (sticky session).

### Схема работы

```
Твой сервер (Nordic)
  ├── TimofeyevAG11  → прокси IP-1 (Москва, Билайн)    ← sticky
  ├── RysyevVO       → прокси IP-2 (Москва, МТС)       ← sticky  
  ├── Новый партнёр  → прокси IP-3 (СПб, Ростелеком)   ← sticky
  └── ...
```

**Sticky** — IP не меняется между сессиями (в отличие от rotating, где IP прыгает каждый запрос).
Profi видит: «аккаунт стабильно с одного IP и города» → без подозрений.

### Как включить для источника

В `Source.config` (поле `config` в таблице `sources`) добавить:

```json
{
  "login": "partnerLogin",
  "password": "***",
  "antiDetect": { "mode": "balanced" },
  "proxy": "socks5://user:pass@ip-прокси:1080"
}
```

Поддерживаются протоколы: `socks5://`, `http://`, `https://`.

### Варианты прокси (от дорогих к дешёвым)

| Тип | Провайдер | За 1 IP/мес | За 5 IP/мес | Особенности |
|-----|-----------|------------|------------|-------------|
| **ISP прокси** (статические резиденшл) | BrightData, Smartproxy | ~$2-3 | ~$10-15 | Выглядят как домашние, надёжные |
| **VPS + SOCKS5** | Timeweb, Selectel, Beget | ~$3-4 | ~$15-20 | Свой сервер, full control |
| **Datacenter прокси** | Любой | ~$0.5-1 | ~$3-5 | Быстрые, но Profi может детектить |

### Рекомендация

- **До 3 источников** — прокси не обязательны, стелс справляется
- **5+ источников** — минимум 5 VPS за ~$15/мес (по $3 за штуку) или ISP-прокси за ~$10-15/мес
- **20+ источников** — децентрализация: агент на ПК каждого партнёра вместо прокси

### Код

Прокси поддерживаются на уровне коннектора (`profi.ts`). При создании контекста Playwright:

```typescript
const contextOptions = {
  // ... обычные настройки
};
if (config.proxy) {
  contextOptions.proxy = { server: config.proxy };
}
const context = await browser.newContext(contextOptions);
```

Достаточно прописать `proxy` в конфиге источника — и весь трафик этого
аккаунта пойдёт через указанный прокси. Менять код не нужно.
