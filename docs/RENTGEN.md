# Рентген сайта — `/rentgen`

Бесплатный сервис хаба: вставил ссылку — получил скриншот сайта с подсветкой поверх. Цель — **показать ошибки визуально**, так чтобы владелец понял проблему без отчёта на 30 пунктов. В конце — переход в Техосмотр за полным разбором.

Статус: ТЗ (26.10.2026). Задачи — `docs/PLAN_2026-08-10.md`, блок D (D.13–D.18).

---

## 1. Позиционирование

| | Рентген | Техосмотр |
|---|---|---|
| Вопрос | «Что на сайте сломано — покажи пальцем» | «Готов ли сайт к рекламе и что чинить первым» |
| Результат | Скриншот со слоями + короткий список | Балл, категории, план, PDF |
| Время | до 1 минуты | 1–3 минуты |
| Роль | Вход в воронку, «вау-картинка» для клиента | Основной продукт |

Аудитория: владельцы сайтов (увидеть свои ошибки), директологи и веб-студии (показать клиенту, почему сайт надо чинить). PNG со слоями — как в «Показе», можно отправить клиенту.

## 2. Слои (по очереди)

1. **Клики** — MVP, этот документ подробно (раздел 4).
2. **Ошибки** — контраст, мелкий текст на телефоне, элемент с горизонтальным скроллом, картинки без alt, поля форм без подписи. Основа: [axe-core](https://github.com/dequelabs/axe-core) (MPL-2.0) + наши проверки мобильной версии. Координаты axe не отдаёт — добираем через Playwright по селектору.
3. **Внимание** — прогноз тепловой карты и порядка взгляда. Модель MSI-Net из [Foveacast](https://github.com/khawkins98/Foveacast) (MIT), обучена на [UEyes](https://github.com/YueJiang-nj/UEyes-CHI2023) (CC BY 4.0 — нужна атрибуция). ONNX ~57 МБ, `onnxruntime-node` на сервере. Ценность — в связке с координатами: «кнопка заявки получает 4% внимания, слайдер — 38%». В интерфейсе честная подпись: прогноз модели, не айтрекинг; хуже работает на тёмных темах и плотных таблицах.
4. **Первый экран** — уже есть в Техосмотре (`FoldMark`: h1, cta, phone, form, trust). Переиспользуем.

## 3. Что не делаем

- Не встраиваем Sa11y / ANDI / букмарклеты во фрейм с чужим сайтом — браузер не пустит скрипт в чужой origin. Только серверный рендер + скриншот.
- Не пишем в `Lead` / `saveAndNotify`, не трогаем Profi и агентов партнёров.
- Не собираем выдачу Яндекса.
- Не показываем «вердикт» и балл — это территория Техосмотра.

## 4. MVP: слой «Клики»

### 4.1 Классы элементов

| Цвет (токен) | Класс | Как определяем |
|---|---|---|
| зелёный `--green` | `ok` | `a[href]` на http(s) с ответом 2xx/3xx; `tel:` / `mailto:` / мессенджеры с валидным адресом; якорь `#id` на существующий блок; `#popup:…` и подобные, если клик открыл окно; кнопка отправки в `form`; пункт с подменю; уже выбранная вкладка (`aria-selected/pressed/current`, класс `active`); элемент, на клик по которому страница отреагировала |
| красный `--red` | `dead` | Только то, что сломано наверняка: `href` пустой / `#` / `javascript:` и клик ничего не делает; якорь на несуществующий блок; ссылка с 404/410/5xx (внутренняя — любой 4xx); домена не существует; неполный `tel:` / `mailto:` без адреса |
| жёлтый `--amber` | `fake` | Выглядит как кнопка (фон/рамка, padding, короткий текст, курсор-рука или класс btn), но клик ничего не делает; **кнопка `<button>`, не отреагировавшая на клик** — «проверьте, возможно, уже выбрана» |
| жёлтый `--amber` | `small` | Только телефон: WCAG 2.2 (2.5.8) — цель < 24 px и круг 24 px вокруг центра задевает соседнюю цель |
| серый `--ink-muted` | `unknown` | Нельзя уверенно сказать: не успели прощёлкать, элемент перекрыт (настоящий клик не прошёл), внешний сайт не дал проверить ссылку (403/429/таймаут) |

Ссылки на `tel:` / `mailto:` / `t.me` / `wa.me` помечаем как «контакт» — отдельная иконка в списке, это полезно владельцу само по себе.

### 4.2 Сбор (в браузере)

- Движок Техосмотра: `src/lib/diagnost/render.ts` — `guard()` (защита от приватных адресов), `openPage()`, `clearPopups()`. Вынести общее в `src/lib/browser/` или импортировать из diagnost — без копипаста.
- Два контекста: ПК (viewport как у Техосмотра) и телефон 390×844, `isMobile`, `hasTouch`.
- Перед снимком — плавная прокрутка до низа и обратно (lazy-load), затем `screenshot({ fullPage: true })`, JPEG. Потолок высоты: ПК 8000 px, телефон 6000 px (`clip`), дальше — пометка «страница обрезана».
- Скрипт `COLLECT_CLICKS` в странице: кандидаты `a, button, input[type=submit|button|image], [role=button], [role=link], [onclick], [tabindex]` + «кнопочные» `div/span` по эвристике. Для каждого: `box` в **пикселях документа** (`rect + scrollY`), `label` (текст / aria-label / title / value, ≤ 80 символов), `tag`, `href`, `inForm`, `cssPath` (короткий, для отладки).
- Вместо поиска обработчиков — **пробный клик**: настоящий клик Playwright (виджеты игнорируют синтетические события), при перекрытии — события `pointer/mouse/click`. Реакция: изменения DOM сверх фонового шума, смена адреса, fetch/xhr (кроме аналитики), новое окно, диалог, копирование в буфер. Одинаковые элементы (тег + класс + подпись) щёлкаем один раз. Лимит: ПК 20 элементов / 25 с, телефон 10 / 12 с, результаты ПК переиспользуются.
- Снимок — кусками по высоте окна со склейкой, не `fullPage`: `captureBeyondViewport` вызывает resize, и сайт перестраивает вёрстку.
- Лимит: 300 элементов на вид, дедуп по `href + label + округлённый box`.

### 4.3 Честность классификации

- React / Vue / Angular (детект по `__reactFiber*`, `__vue__`, `ng-version`, `data-reactroot`) вешают обработчики на корень → отсутствие слушателя на элементе ничего не значит. Для таких сайтов кандидаты без `href` и без слушателя — `unknown`, не `fake`.
- Ссылки, закрытые антиботом (403 от Cloudflare и т. п. на внешние домены), — `unknown`, не `dead`. Внешние домены проверяем только на 404/410/5xx/DNS.
- В интерфейсе: «Жёлтым — то, что похоже на проблему. Проверьте руками».

### 4.4 Проверка ссылок (на сервере)

- Уникальные URL, до 60 на скан, параллельно 6, таймаут 5 с, `HEAD` → при 405/501 `GET` с `Range: bytes=0-0`.
- Тот же фильтр приватных адресов, что в `guard()`, + резолв DNS до запроса.
- Редиректы до 5; итоговый статус и цепочка — в результат.

### 4.5 Данные

Новая модель (не расширяем `DiagnostAudit`):

```prisma
model RentgenScan {
  id         String    @id @default(uuid())
  slug       String    @unique
  ownerToken String    @map("owner_token")
  ipHash     String?   @map("ip_hash")
  url        String
  host       String
  /// queued | running | done | failed
  status     String    @default("queued")
  progress   Int       @default(0)
  result     Json?
  error      String?   @db.Text
  startedAt  DateTime? @map("started_at")
  finishedAt DateTime? @map("finished_at")
  createdAt  DateTime  @default(now()) @map("created_at")

  @@index([status, createdAt])
  @@map("rentgen_scans")
}
```

`result`:

```ts
type RentgenResult = {
  views: {
    desktop: RentgenView;
    mobile: RentgenView | null;
  };
  framework: "react" | "vue" | "angular" | null;
  linksChecked: number;
};
type RentgenView = {
  shot: string;            // storage/rentgen/<id>-desktop.jpg
  width: number;
  height: number;          // высота снимка
  truncated: boolean;
  items: Array<{
    n: number;             // номер на картинке (только для проблем)
    kind: "ok" | "dead" | "fake" | "small" | "unknown";
    contact?: "tel" | "mail" | "messenger";
    label: string;
    href?: string;
    status?: number | null;
    reason: string;        // «Ссылка ведёт на страницу 404», «Похоже на кнопку, но не нажимается»
    box: { x: number; y: number; w: number; h: number }; // px документа
  }>;
};
```

Скриншоты: `storage/rentgen/` (как `storage/diagnost/`), раздача через `/api/rentgen/[slug]/shot?view=desktop`. Чистка старше 30 дней — тем же кроном, что у Техосмотра (если есть) или новым.

### 4.6 Очередь и процессы

- Новый PM2-процесс **не заводим**. `src/collectors/diagnost-worker.ts` забирает задачи из обеих очередей: сначала `DiagnostAudit`, потом `RentgenScan`. Один браузер за раз — нагрузка на хаб не растёт сверх Техосмотра.
- Лимиты (`src/lib/diagnost/access.ts` как образец): 10 сканов в сутки на IP; тот же URL за последний час — отдаём готовый скан.

### 4.7 API

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/rentgen` | `{ url }` → валидация, лимиты, создание скана → `{ slug, reused }` |
| GET | `/api/rentgen/[slug]` | статус, прогресс, `queueAhead`, `result` (без путей к файлам; `shot` — URL снимка) |
| GET | `/api/rentgen/[slug]/shot/[view]` | JPEG снимка, `view` = `desktop` \| `mobile` |

Доступ публичный, без входа. Лимиты в `src/lib/rentgen/data.ts`:
- 10 новых сканов в сутки на IP (`RENTGEN_DAILY_LIMIT`), админ без лимита;
- не больше 20 сканов в очереди одновременно → 429;
- тот же адрес за последний час (готов или в работе) → отдаём существующий `slug`, лимит не списывается;
- кука владельца `rg_owner`, `ipHash` = sha256(`rentgen:<ip>`).

Прогресс: 5 — взят в работу, 10 — ПК, 55 — телефон, 85 — ссылки, 100 — готово.

### 4.8 Интерфейс

Сделано (D.16):
- `/rentgen` — заголовок, поле адреса, справа настоящий снимок первого экрана нашей главной с рамками (`npx tsx scripts/rentgen-demo.ts` → `public/rentgen/demo.jpg` + `src/lib/rentgen/demo.json`), полоса-легенда из 4 цветов, «Мои проверки» по куке `rg_owner`, «Как проверяем / Чего не делаем».
- `/rentgen/r/[slug]` — экран ожидания (полоса + 4 этапа по `progress`, место в очереди), затем результат:
  - переключатели «ПК / Телефон» и «Все / Только проблемы»;
  - снимок, рамки в процентах от размера документа (масштаб любой), номер-метка у проблем;
  - режим «плёнка» («Только проблемы», по умолчанию, если проблемы есть): снимок обесцвечен и затемнён, проблемные места — цветные окна (фон рамки = тот же снимок без фильтра);
  - справа (на телефоне — над снимком) сводка по 4 группам и список проблем; клик по пункту → прокрутка к рамке, клик по рамке → пункт в списке;
  - результаты `noindex`.

Группы: «Работает» (ok), «Не работает» (dead), «Проверьте» (fake + small), «Не проверяли» (unknown) — `src/lib/rentgen/groups.ts`.

Дизайн (согласован по design-anti-slop): нейтральная тёмная оболочка `.rg-*` на токенах проекта (`src/app/rentgen/rentgen.css`), главная кнопка — светлая на тёмном; цвет только у рамок, чтобы интерфейс не спорил с результатом. Без размытия фона, светящихся пятен и ряда одинаковых карточек.

- «Скачать картинку» — canvas на клиенте (`src/components/rentgen/export-shot.ts`): шапка с адресом, датой и сводкой, снимок с рамками (с «плёнкой», если включена), подпись сервиса. JPEG 0.88, ширина 1200 px (снимок телефона — 520 px по центру): PNG длинной страницы весил бы несколько МБ.
- Блок «Кнопки — только часть картины» → `/diagnost?url=<адрес>` — Техосмотр подставляет адрес в форму.
- `/rentgen/r/` закрыт в `robots.ts`, `/rentgen` — в sitemap.

## 6. Риски

- **Антибот / капча** — снимок заглушки. Детектим (как в Техосмотре) и честно пишем «сайт не пустил проверку».
- **Липкие шапки** на full-page снимке и **анимации появления** (элементы с `opacity:0` до скролла) — прокрутка перед снимком, `reducedMotion: "reduce"` в контексте.
- **Ложные `fake`** — главный риск доверия. Эвристику держим консервативной: лучше `unknown`, чем ошибиться.
- **Очень длинные страницы** — потолок высоты и пометка «обрезано».
- **Нагрузка на хаб** — общая очередь с Техосмотром, один браузер.

## 7. Слой «Ошибки» (D.18a)

Цель: на том же снимке показать то, что мешает **прочитать и заполнить** страницу. Не балл и не аудит доступности целиком — только находки с координатами.

**Где считаем.** В `renderView` после снимка и до пробных кликов (клики меняют страницу). Отдельного прохода браузера нет — +1–3 с на вид.

**Источник 1 — axe-core** (MPL-2.0, без изменений, скрипт вставляется в страницу). Правила только «с местом на странице»:

| Правило axe | Что пишем | Цвет |
|---|---|---|
| `color-contrast` | «Текст плохо читается: контраст 2,1:1, нужно от 4,5:1» | красный, если < 3:1, иначе жёлтый |
| `label`, `select-name` | «Поле формы без подписи — непонятно, что вводить» | красный |
| `image-alt`, `input-image-alt` | «Картинка без описания (alt)» | жёлтый |
| `button-name` | «Кнопка без названия — экранный диктор скажет просто „кнопка“» | жёлтый |
| `link-name` | «Ссылка без текста — непонятно, куда ведёт» | жёлтый |

Координаты — в том же скрипте страницы: `document.querySelector(target)` → `getBoundingClientRect()` + прокрутка. Цели внутри iframe и shadow DOM пропускаем.

**Источник 2 — свои проверки, только телефон:**
- «Блок шире экрана — страница ездит вбок» (красный): только если страница **реально** прокручивается вбок (`scrollTo(100,0)` → `scrollX > 0`); показываем верхние элементы, вылезающие за правый край, до 10.
- «Мелкий текст: 10 px, на телефоне читать трудно» (жёлтый): видимый текст с `font-size < 12px`, до 30.

**Лимиты:** контраст — до 40 элементов на вид, остальные правила — до 30; ниже обрезки снимка не берём; нулевые и невидимые пропускаем.

**Данные:** `RentgenView.issues?: IssueItem[]` — `{ n, rule, severity: "error" | "warn", label, reason, box }`. Старые сканы без поля — переключатель слоя неактивен.

**Интерфейс:** переключатель «Клики / Ошибки» над снимком; список сгруппирован по правилу с числом; «плёнка» и «Скачать картинку» работают для обоих слоёв (легенда картинки — по слою).

**Честная подпись:** «Автоматическая проверка находит примерно треть проблем доступности; остальное — только ручная».

## 8. Слой «Внимание» (D.18b, после «Ошибок»)

- Модель MSI-Net (Foveacast, MIT), ONNX ~57 МБ, `onnxruntime-node` в воркере. Вход — первый экран ПК 1440×900 и телефона 390×844, выход — карта 0…1.
- Слой: полупрозрачная тепловая карта поверх первого экрана + доля внимания на ключевых элементах из «Кликов» (главная кнопка, телефон, форма): «кнопка заявки — 4% внимания, слайдер — 38%».
- Атрибуция UEyes (CC BY 4.0) в подписи слоя; подпись «прогноз модели, не айтрекинг; хуже на тёмных темах и плотных таблицах».
- Перед стартом: проверить лицензию весов, память воркера (+~300 МБ), время на CPU (цель < 3 с на кадр).

**Проверка (26.10.2026, черновик в `/tmp/rg-attn`, в проект не входит):**
- Лицензии: Foveacast — MIT, MSI-Net (alexanderkroner/saliency) — MIT, веса (khawkins98/foveacast-training, релиз v0.2.0) — MIT; UEyes — CC BY 4.0, нужна атрибуция в подписи слоя.
- Веса: `foveacast-v3-3s-int8.onnx` — 31,7 МБ (fp16 — 56,5 МБ). Качество int8 ≈ fp16: CC 0,706 против 0,707 на тесте UEyes. Есть варианты 1s / 3s / 7s.
- Вход `[1, 3, 240, 320]`, RGB 0–255 без нормализации, вписать с полями 126; выход `[1, 1, 240, 320]` уже 0…1.
