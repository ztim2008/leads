# SaaS-архитектура Konversus Leads AI

## Целевая модель

Клиент регистрируется → оплачивает тариф → подключает источники → получает заявки в Telegram и панели.

У каждого клиента — изолированный контур: свои источники, свои настройки, свой AI-ключ, свой Telegram-бот.

---

## 1. ПЛАН РАБОТ (4 фазы)

### Фаза A: Изоляция Worker (2-3 дня)

**Проблема:** Один Playwright-браузер на всех. Один `cachedPage` на всех.

**Решение:** Worker обрабатывает источники ПООЧЕРЕДИ, но каждый в своём браузерном контексте.

```
Цикл опроса (каждые 3 мин):
  для каждого workspace:
    для каждого включённого source в workspace:
      1. Создать новый BrowserContext
      2. Загрузить cookies/логин для этого source
      3. Зайти на площадку
      4. Собрать заявки
      5. Закрыть BrowserContext
```

**Конкретные изменения:**
- `profi.ts`: убрать глобальные `cachedPage`, `cachedBrowser`
- Каждый `fetchLeads()` создаёт свой браузер → логинится → парсит → закрывает
- Добавить таймаут на браузер (30 сек максимум)
- Повторные попытки при ошибке (до 2 раз)

### Фаза B: BullMQ очередь (2 дня)

**Проблема:** `setInterval` — нет retry, нет мониторинга, нет параллельности.

**Решение:** BullMQ с Redis (уже в зависимостях, Redis запущен).

```
Scheduler (новый процесс PM2):
  каждые 3 мин → для каждого source → queue.add("fetch-leads", { sourceId })

Worker (новый процесс PM2):
  слушает очередь "fetch-leads" →
    → берёт sourceId → processSource(sourceId) →
    → успех → удалить из очереди
    → ошибка → retry через 1 мин (до 3 попыток)
```

**Преимущества:**
- Retry с backoff при ошибках Playwright/AI
- Мониторинг: сколько в очереди, сколько failed
- Параллельная обработка (concurrency: 3)
- Stalled jobs detection (если worker завис)
- Не теряются заявки при перезапуске

### Фаза C: Subscription-лимиты (1 день)

**Проблема:** Модель Subscription есть, но не проверяется.

**Решение:** Проверка лимитов перед каждым действием.

```typescript
// Перед сбором заявок
const sub = await getActiveSubscription(workspaceId);
if (!sub) return; // нет активной подписки

// Проверка лимита заявок в день
const todayLeads = await countTodayLeads(workspaceId);
if (todayLeads >= sub.leadsPerDay) {
  console.log(`[worker] Лимит заявок исчерпан для workspace ${workspaceId}`);
  return;
}

// Проверка AI-анализ
if (!sub.aiAnalysis) {
  apiKey = null; // не делаем AI-анализ
}

// Проверка генерации откликов
if (!sub.aiResponses) {
  skipResponses = true;
}
```

**Тарифы зашить в код:**
| План | Источников | Заявок/день | AI | Отклики | Цена |
|------|-----------|-------------|-----|---------|------|
| Бесплатный | 1 | 50 | ❌ | ❌ | 0 ₽ |
| Pro | 5 | 500 | ✅ | ✅ | 990 ₽/мес |
| Бизнес | ∞ | ∞ | ✅ | ✅ | 2 490 ₽/мес |

### Фаза D: Стилизация (1 день)

**Проблема:** Tailwind в sources/page.tsx, inline в остальных, shadcn не используется.

**Решение:** Всё на CSS-переменных + Inline Styles (как в 90% проекта).

- Удалить `shadcn` из зависимостей
- `sources/page.tsx` переписать на inline styles
- Компоненты `src/components/ui/` оставить как есть
- Все формы — единый стиль через CSS-переменные

## 2. АРХИТЕКТУРА SAAS

### Схема данных (уже есть, проверить)

```
User (1) ──── (N) Workspace
                    ├── (N) Source
                    ├── (N) Lead → LeadAnalysis, Response
                    ├── (1) Settings
                    └── (1) Subscription
```

### Путь клиента

```
1. Регистрация на /auth?tab=register
2. Автосоздаётся Workspace + Settings + Бесплатная Subscription
3. Клиент заходит в Источники → подключает Profi.ru
4. Воркер начинает собирать заявки (до 50/день на бесплатном)
5. Клиент видит заявки в панели
6. Хочет больше → оплачивает Pro → лимиты повышаются
```

### Изоляция данных

- Каждый API-запрос проверяет `workspaceId` через middleware
- Worker передаёт `workspaceId` во все операции
- Playwright-браузер создаётся заново для каждого source
- API-ключи и токены — в Settings каждого workspace

## 4. МОНЕТИЗАЦИЯ (ЮKassa)

### Интеграция

```
1. Клиент нажимает «Оплатить Pro» в панели
2. Создаётся платёж в ЮKassa → редирект на оплату
3. ЮKassa шлёт webhook на /api/billing/webhook
4. Webhook проверяет подпись → активирует Pro-подписку
5. Клиент получает доступ ко всем функциям
```

### Что нужно сделать:
- Страница `/dashboard/billing` — тарифы и история платежей
- `/api/billing/create` — создание платежа
- `/api/billing/webhook` — приём уведомлений от ЮKassa
- Крон для деактивации истёкших подписок
