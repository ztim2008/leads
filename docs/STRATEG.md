# Стратег — рекламная стратегия по сайту клиента

> Внутренний раздел админки. Не Job Radar и не заявка партнёра.  
> Читать этот файл, если задача про Стратег, бриф, аудит сайта, Wordstat, Директ или коммерческое предложение.

**Продакшен:** https://leads.konversus.ru/dashboard/admin/briefs · веб `leads-konversus` · воркер PM2 `leads-briefs` · порт `3005`

Пилот: https://www.k-spec.ru/ · ниша «Производство спецодежды» · регион «Московская область, Подольск».

---

## Что это

Стратег по открытым страницам сайта собирает факты и готовит основу для Яндекс.Директа и коммерческого предложения. Это инструмент админа и подключённого директолога, не массовый продукт.

```
сайт (HTTP, до 5 страниц)
        → факты / гипотезы / рекомендации
        → черновик стратегии и КП
        → человек ставит цену и срок
```

Показы Wordstat и конкуренты в выдаче в этот контур пока не входят.

---

## Договор о доверии

| Вид | Откуда | Пример |
|-----|--------|--------|
| Факт | страница сайта или ответ API | телефон, заголовок, цитата |
| Гипотеза | модель, и только с цитатой со скачанной страницы | «на услугах есть порог опта» |
| Рекомендация | модель, тоже с цитатой | что поправить до запуска |

Нет источника — пишем «нет данных». Не выдумываем показы, ставки, бюджеты конкурентов и прогноз заявок. В кабинет Директа ничего не публикуем.

Модель: OpenRouter, `deepseek/deepseek-chat`. Ключ берётся из `OPENROUTER_API_KEY`, иначе из самой новой строки `Settings.openrouterKey`. Если модели нет, в отчёте остаются только факты со страниц.

Конкуренты в выдаче — тот же платный Search API, что и Wordstat. Пока счёт не оплачен, их не подключаем.

## Wordstat

Код клиента есть: `src/lib/briefs/wordstat.ts`. Вызов выключен. Повторный разбор сайта в API не ходит и денег не списывает.

Включить позже, когда счёт в AI Studio станет активным:

```
BRIEFS_WORDSTAT=1
```

Рядом уже лежат `YANDEX_SEARCH_API_KEY` и `YANDEX_CLOUD_FOLDER_ID`. Идентификатор каталога начинается с `b1` и содержит 20 символов. Идентификатор сервисного аккаунта (`aje…`) в эту строку не ставить: если там не каталог, воркер попробует узнать каталог сам. После правки `.env` перезапустить `leads-briefs`.

Ключ в чат и в git не класть. `.env` в коммит не входит.

Тариф API с 18 мая 2026: топ запросов и динамика — 20 ₽ за 1000 обращений, разбивка по регионам — 50 ₽ за 1000. Справочник регионов бесплатный. Сайт wordstat.yandex.ru для человека по-прежнему бесплатный. Один разбор Стратега — три запроса топа.

Регион для пилота: Подольск `10747` важнее «Московская область» в той же строке. Незнакомый город — Россия `225`, и это надо прямо написать в отчёте.

## Как пользоваться

1. Админ открывает «Стратег» и создаёт разбор: адрес сайта, ниша, регион, цель.
2. Воркер `leads-briefs` скачивает до 5 страниц по HTTP, без браузера.
3. На карточке четыре слота: предложение, цены, связь, телефон. Ниже факты, гипотезы, рекомендации.
4. Семантика показывает, что показы отложены.
5. Стратегия и коммерческое предложение собираются из уже лежащих фактов. Цена и срок — «Заполняет человек».
6. «PDF для мессенджера» скачивает файл для чтения с телефона: узкие страницы и таблицы, не лист для печати. «Скопировать» по-прежнему готовит короткий текст.
7. «Править» меняет формулировку пункта. Заметки внизу — свободный текст человека.
8. «Версия для печати» — тот же отчёт без оболочки кабинета.

Директолога админ подключает по email уже существующего пользователя. Новую учётку ради Стратега не заводить. Список хранится в `AppConfig.briefsEmails`. Чужой кабинет через имперсонацию в раздел не пускает. Роль sales сама по себе доступа не даёт.

## Данные

PostgreSQL `leads_ai`, не MySQL.

| Таблица | Зачем |
|---------|--------|
| `brief_projects` | сайт, ниша, регион, цель, статус |
| `brief_runs` | прогон: очередь, ошибка, скачанные страницы |
| `brief_findings` | пункт отчёта: секция, вид, цитата |
| `brief_documents` | заметки человека |

Секции пункта: `site`, `semantics`, `competitors`, `strategy`, `proposal`. Сейчас пишется `site`. Семантика появится в таблице только после `BRIEFS_WORDSTAT=1`. Черновик стратегии и объявлений на экране считается из фактов сайта и в таблицу отдельно не кладётся. PDF собирается в момент скачивания. Статусы проекта: `queued`, `running`, `ready`, `failed`.

PDF для мессенджера — узкая страница 400×720 pt, шрифт DejaVu Sans с сервера, таблицы на белом фоне из светлых токенов. Это не версия для печати.

## Дальше

Кабинет Директа — только после человека, когда черновики посмотрят на живом клиенте. Два блока «хорошо / плохо» собираются из фактов HTML: директологу — что можно взять в объявление, разработчику — что поправить в title, H1, описании, alt и noindex. Позиции в поиске и ссылочный профиль туда не входят. Wordstat — когда партнёр оплатит счёт и в `.env` появится `BRIEFS_WORDSTAT=1`.
