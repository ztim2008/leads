## 🎯 Модель продукта (не SaaS)

> **Обновлено:** 11.08.2026 · Подключение партнёров **только администратором**.

Сервис **не** публичный SaaS. Три роли:

| Роль | Кто | Доступ |
|------|-----|--------|
| **Админ** | Алексей | Оператор: партнёры, VPS, Пульт, доктор. **Не** сборщик на хабе |
| **Партнёр** | Клиент | Вход → заявки + Telegram. Если админу нужны заявки — онбординг как партнёру |
| **Агент (продажи)** | Находит партнёров | Вне продукта или read-only |

**Не делаем:** публичная регистрация, self-service онбординг, автоматический биллинг как SaaS.  
**Делаем:** операторская админка + VPS agent v2 на каждого партнёра.

Публичная регистрация отключена (`/api/auth/register` → 403, `/auth` — только вход).

## 🧭 Философия (незыблемые принципы)

### Золотое правило

> **Ждун должен быть НЕОТЛИЧИМ от человека. Если не может работать безопасно — лучше НЕ РАБОТАТЬ, чем спалиться и потерять аккаунт.**

Один аккаунт Profi = **актив на годы**. Потеря **необратима**. Любой код, который рискует аккаунтом, хуже отсутствия сбора.

### 10 заповедей (из `docs/ANTI_BLOCK_PLAN.md`)

| # | Принцип | Реализация |
|---|---------|------------|
| 1 | **Один IP = один аккаунт** | VPS на партнёра, не прокси-ротация |
| 2 | **Один браузерный профиль = один аккаунт** | Persistent context, куки на диске |
| 3 | **Человеческие задержки** | 3–7 мин между проверками, скролл, случайные клики |
| 4 | **Не перезаходить без нужды** | Persistent profile, вход не чаще 1 раза в 4 часа |
| 5 | **Circuit breaker** | 3 ошибки → стоп 60 мин → алерт |
| 6 | **Exponential backoff** | +2 мин → +10 мин → +60 мин |
| 7 | **Persistent состояние** | CB и кулдауны в БД/файле, не в памяти |
| 8 | **Тихий режим при ошибках** | Молчим, не спамим Profi запросами |
| 9 | **Внешний health-check** | Мониторинг не внутри ждуна |
| 10 | **Graceful degradation** | Profi упал → Kwork работает, хаб жив |

### Архитектурная философия

```
┌─────────────────────────────────────────┐
│  ХАБ (leads.konversus.ru)               │
│  Только: UI + API + БД + Telegram       │
│  НИКАКОГО Playwright для Profi          │
└──────────────────┬──────────────────────┘
                   │ HTTPS
         ┌─────────┼─────────┐
         ▼         ▼         ▼
      VPS #1    VPS #2    VPS #N
      1 IP      1 IP      1 IP
      1 Profi   1 Profi   1 Profi
      Agent v2  Agent v2  Agent v2
```

**Хаб — тонкий.** Вся «грязная» работа с браузером — **только на VPS партнёра**.

### Что НЕ делаем (никогда)

```
❌ Playwright для Profi на хабе (109.196.165.106)
❌ pm2 start leads-profi / profi-watcher на хабе
❌ Авто-рестарт при ошибке входа
❌ Больше 3 попыток входа подряд
❌ Два ждуна на один аккаунт
❌ Правки production через SSH без git
❌ Хранить состояние CB только в памяти
❌ Восстанавливать worker.ts
```

**Политика в коде:** `src/config/hub.ts` → `profiOnHub: false`

### Модель

Два Telegram-канала **не смешивать:** партнёр — заявки + свои фильтры; админ — ops (offline, CB, сводка, доставка в TG). Тот же `@leadskonversus_bot`, разные chat_id.

| Кто | Что настраивает | Где |
|-----|-----------------|-----|
| **Партнёр** | Плюс/минус **заголовка** и плюс/минус **текста** (со склонениями), часы 08–22, бюджет от–до, без бюджета, пол по имени | Кабинет `/dashboard/settings` (вход: email + пароль из карточки) |
| **Админ** | Profi, VPS, лимит/месяц, вкл/выкл сбора, antiDetect, интервал | Админка / Пульт |

Дашборд партнёра: заявки + **фильтры** (4.10). Единый бот (4.9) не дублирует те же поля в v1.

### Безопасность Profi (незыблемо)

- Партнёр **не** меняет: логин/пароль Profi, интервалы проверки, antiDetect, вкл/выкл сбора, VPS.
- Бюджет от–до и «без бюджета» — партнёр (4.10).
- **Стоп сбора — только админ.** Партнёр не включает/выключает ждуна (лишний login = риск бана).
- Часы сбора: только в рамках **08:00–22:00 МСК** (min 6 ч «тишины»), по умолчанию из админки.
- Ключевые/минус-слова: лимит длины, валидация; применение на **следующем** `GET /api/v2/agent/config` (**без** рестарта Playwright, **0** новых входов Profi).
- Смена фильтров: не чаще 1 раза в 4 ч (cooldown в БД).

## Этап 4.11 — Дневная выработка на Пульте

**Дедлайн:** после обкатки фильтров 4.10 · **Статус этапа:** 🟡 **В работе**

> **Цель:** админ и агент каждое утро с 00:00 МСК видят, сколько собрано заявок «за сегодня» — без ручного сброса БД и без опроса партнёра.

### Принцип «сброса»

Физически заявки **не удаляем**. Счётчик дня = `createdAt >= 00:00 МСК`. В полночь цифра сама становится 0; история в БД и у партнёра сохраняется.

### Что показать оператору

| Где | Метрика |
|-----|---------|
| **Пульт** (карточка / строка партнёра) | Сегодня **собрано** · **в TG** · последняя заявка (время + короткий title) · **вчера** для сравнения |
| **Сводка флота** | Всего сегодня по всем партнёрам; кто молчит в рабочие часы при online |
| **Telegram админу** (опционально, утро ~09:00) | Краткая строка: `пилот: N сегодня · вчера M` — не чаще 1×/сутки |

Связка с **5.8:** «собрано» = БД за день; «в TG» = подтверждённые доставки за день. Расхождение по-прежнему видно.

### Причины отсева (фаза 2)

Чтобы отличить «мало рынка» от «жёсткие фильтры», агент v2 шлёт безопасные **счётчики ленты** (без смены частоты, без рестарта входа):

| Причина | Зачем |
|---------|--------|
| keywords / минус | фильтр партнёра слишком узкий/широкий |
| бюджет / без бюджета | вилка отсекает поток |
| пол по имени | М/Ж режет неизвестные имена |
| вне часов | нормальная тишина ночью |

Пока счётчиков нет — на Пульте только БД/TG/вчера/последняя. Отсев — отдельным подпунктом после стабильного 4.10.

| # | Задача | Статус | Файлы / заметки |
|---|--------|--------|-----------------|
| 4.11.1 | Пульт: сегодня / вчера / последняя заявка по партнёру | ✅ | API + таблица; live: 29 сегодня / 13 вчера |
| 4.11.2 | Карточка «выработка дня» (флот + выбранный партнёр) | ✅ | Сегодня/вчера/TG/последняя; норма 8–15 — ориентир |
| 4.11.3 | Утренняя TG-сводка админу (~09:00 МСК), 1×/сутки | ⚪ | health-monitor; не слать копии заявок |
| 4.11.4 | Safe-счётчики отсева с agent v2 → хаб | ⚪ | Без рестарта входа; только после обкатки 4.10 |
| 4.11.5 | Пульт: разбивка «отсеяно по причине» | ⚪ | Только если 4.11.4 готов |

**DoD этапа 4.11:**

1. После 00:00 МСК счётчик «сегодня» стартует с нуля без удаления лидов.
2. Админ на Пульте видит по каждому партнёру: собрано сегодня, TG сегодня, вчера, время последней заявки.
3. В рабочие часы при online и 0 за день понятно, что смотреть (фильтры / рынок), а не «агент мёртв».
4. Пилот не рестартится ради метрик.

**Не в scope 4.11:** физический wipe лидов; deep scan ради статистики; ускорение интервала Profi.
