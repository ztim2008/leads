**Потеряно:**
- Аккаунт **TimofeyevAG11** — годы репутации, отзывы, история
- Аккаунт **RysyevVO** — то же
- Восстановление **невозможно** (даже с телефона — Profi удаляет навсегда)

### Вторая боль — онбординг партнёров

Сейчас подключение одного партнёра = **ручная работа админа на ~1 час**:

| Шаг | Кто | Барьер |
|-----|-----|--------|
| VPS в KZ (~2000 ₽) | Партнёр или админ | Непонятно зачем |
| SSH + `curl \| bash` | Админ | Партнёр не может сам |
| Profi логин/пароль | Партнёр | Доверие |
| Bot Token + Chat ID | Партнёр | Техническая грамотность |
| Source в админке | Админ | Не масштабируется |

**Итог:** продукт технически работает, но **не масштабируется** и **убивает аккаунты** при сбоях.

### Третья боль — архитектурный хаос (до Phase 0)

Было **4 параллельных способа** собирать Profi:

1. `profi-watcher.ts` (PM2 leads-profi)
2. `worker.ts` (1024 строки, мёртвый)
3. `public/agent/agent.mjs` (упрощённая копия без stealth)
4. 17× `scripts/test-profi-*` (эксперименты)

Плюс BullMQ/Redis в зависимостях — **нигде не использовались**.

## 🧭 Философия (незыблемые принципы)

### Золотое правило

> **Ждун должен быть НЕОТЛИЧИМ от человека. Если не может работать безопасно — лучше НЕ РАБОТАТЬ, чем спалиться и потерять аккаунт.**

Один аккаунт Profi = **актив на годы**. Потеря **необратима**. Любой код, который рискует аккаунтом, хуже отсутствия сбора.

### 10 заповедей (из `docs/ANTI_BLOCK_PLAN.md`)

| # | Принцип | Реализация |
|---|---------|------------|
| 1 | **Один IP = один аккаунт** | VPS на партнёра, не прокси-ротация |
| 2 | **Один браузерный профиль = один аккаунт** | Persistent context, куки на диске |
| 3 | **Человеческие задержки** | 3–7 мин между проверками, скролл, случайные клики |
| 4 | **Не перезаходить без нужды** | Persistent profile, вход не чаще 1 раза в 4 часа |
| 5 | **Circuit breaker** | 3 ошибки → стоп 60 мин → алерт |
| 6 | **Exponential backoff** | +2 мин → +10 мин → +60 мин |
| 7 | **Persistent состояние** | CB и кулдауны в БД/файле, не в памяти |
| 8 | **Тихий режим при ошибках** | Молчим, не спамим Profi запросами |
| 9 | **Внешний health-check** | Мониторинг не внутри ждуна |
| 10 | **Graceful degradation** | Profi упал → Kwork работает, хаб жив |

### Архитектурная философия

```
┌─────────────────────────────────────────┐
│  ХАБ (leads.konversus.ru)               │
│  Только: UI + API + БД + Telegram       │
│  НИКАКОГО Playwright для Profi          │
└──────────────────┬──────────────────────┘
                   │ HTTPS
         ┌─────────┼─────────┐
         ▼         ▼         ▼
      VPS #1    VPS #2    VPS #N
      1 IP      1 IP      1 IP
      1 Profi   1 Profi   1 Profi
      Agent v2  Agent v2  Agent v2
```

**Хаб — тонкий.** Вся «грязная» работа с браузером — **только на VPS партнёра**.

### Что НЕ делаем (никогда)

```
❌ Playwright для Profi на хабе (109.196.165.106)
❌ pm2 start leads-profi / profi-watcher на хабе
❌ Авто-рестарт при ошибке входа
❌ Больше 3 попыток входа подряд
❌ Два ждуна на один аккаунт
❌ Правки production через SSH без git
❌ Хранить состояние CB только в памяти
❌ Восстанавливать worker.ts
```

**Политика в коде:** `src/config/hub.ts` → `profiOnHub: false`
