# 🏛 ProektMap: Анти-блокировка Profi — работа над ошибками

> **Дата:** 30 июля 2026  
> **Причина:** 3277 рестартов за час → блокировка обоих аккаунтов Profi  
> **Цена:** потеря заявок на сутки, ручная разблокировка аккаунтов

---

## 🔥 Что произошло (root cause)

```
┌─────────────────────────────────────────────────────────────────┐
│  ЦЕПОЧКА СОБЫТИЙ                                                │
│                                                                  │
│  1. Браузер Playwright упал (ERR_ABORTED)                       │
│     ↓                                                            │
│  2. doCheck() catch → stopWatching() → startWatching()          │
│     ↓                                                            │
│  3. startWatching() → ensureLoggedIn() → не удалось войти       │
│     (Profi запросил SMS/капчу)                                   │
│     ↓                                                            │
│  4. startWatching() вернул false                                 │
│     ↓                                                            │
│  5. profi-watcher.ts: «Не удалось войти» → НЕ ОСТАНОВИЛСЯ      │
│     ↓                                                            │
│  6. Health-check (каждые 10 мин): page умер → startWatching()   │
│     ↓                                                            │
│  7. doCheck() catch → startWatching()                           │
│     ↓                                                            │
│  8. ТРИ механизма одновременно пытаются перезапустить ждуна      │
│     ↓                                                            │
│  9. 3277 попыток входа за 1 час                                  │
│     ↓                                                            │
│  10. Profi: «Это бот! БЛОК!»                                     │
└─────────────────────────────────────────────────────────────────┘
```

### Корневые причины

| # | Проблема | Почему |
|---|----------|--------|
| 1 | **Три механизма рестарта** | doCheck catch + healthCheck + SILENT 30min — все вызывают startWatching без координации |
| 2 | **Нет кулдауна** | При неудачном входе — мгновенная повторная попытка |
| 3 | **Состояние в памяти** | Счётчики ошибок теряются при рестарте PM2 |
| 4 | **Нет circuit breaker** | После N ошибок надо остановиться и алертить, а не продолжать |
| 5 | **Playwright падает** | Браузер нестабилен под нагрузкой, нет перезапуска браузера без пересоздания сессии |
| 6 | **Правки через SSH ломаются** | heredoc/bash крашится, sed не матчит, Python дублирует код |

## 🎯 Принципы анти-блокировки

### Золотое правило
> **Ждун должен быть НЕОТЛИЧИМ от человека. Если не может — лучше НЕ РАБОТАТЬ, чем спалиться.**

### 10 заповедей

| # | Принцип | Реализация |
|---|---------|------------|
| 1 | **Один IP = один аккаунт** | VPS на партнёра |
| 2 | **Один браузерный профиль = один аккаунт** | Persistent контекст, не удалять куки |
| 3 | **Человеческие задержки** | 2-6 мин между проверками, случайный скролл, случайные клики |
| 4 | **Не перезаходить без нужды** | Хранить сессию (куки/localStorage), переиспользовать |
| 5 | **Circuit breaker** | 3 ошибки → стоп на 1 час → алерт админу |
| 6 | **Exponential backoff** | 1-я ошибка: +2 мин, 2-я: +10 мин, 3-я: +60 мин |
| 7 | **Persistent состояние** | Счётчики ошибок и кулдауны — в БД, не в памяти |
| 8 | **Тихий режим при ошибках** | Если не можем работать — молча ждём, не спамим запросами |
| 9 | **Отдельный health-check** | Мониторинг через внешний cron, не через сам ждун |
| 10 | **Graceful degradation** | Если Profi недоступен — переключаемся на Kwork/другие источники |

## 🔧 Circuit Breaker (детально)

```
Состояния:

  [CLOSED] ──ошибка──► [OPEN] ──таймаут──► [HALF-OPEN] ──успех──► [CLOSED]
     ▲                     │                      │
     └──────успех──────────┘    └──ошибка──────────┘

Правила:
  CLOSED:    нормальная работа, считаем ошибки
  OPEN:      после 3 ошибок за 10 минут → стоп на 1 час
  HALF-OPEN: через 1 час → пробный вход. Успех → CLOSED. Ошибка → OPEN ещё на 2 часа

Хранится в БД (таблица agent_state):
  source_id     UUID
  state         ENUM('closed','open','half_open')
  fail_count    INT
  last_fail     TIMESTAMP
  open_until    TIMESTAMP
  alerted       BOOLEAN
```
