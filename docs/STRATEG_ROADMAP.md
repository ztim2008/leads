## Цель

Один разбор сайта даёт три результата:

| Кто читает | Что должен понять |
|------------|-------------------|
| Директолог | Что за сайт и как правильно собрать кампанию: группы, фразы, минус-слова, посадочные, цели Метрики |
| Клиент | Какой потенциал у рекламы и что мешает получать заявки — без выдуманных цифр |
| SEO-специалист | Что ещё исправить на сайте и в каком порядке |

Договор о доверии из [STRATEG.md](STRATEG.md) не меняется: факт со страницы или из API, рекомендация — отдельной колонкой, цифр без источника нет. Общий балл «готовность 73/100» и «конверсия после правок» не делаем: это ломает доверие.

### R.1 — Структура кампании ⚪ · следующий

Отчёт отвечает не только «что за сайт», но и «что включить завтра».

- Группы объявлений из карты посадочных (`landing.ts`). На группу: заготовки фраз из названия раздела и H1, посадочная, черновик объявления.
- Минус-слова по типу бизнеса. Производство и опт: «своими руками», «бесплатно», «вакансии», «б/у», «скачать», «фото». Словари — в коде, по нише, без модели.
- Быстрые ссылки (4–8) из меню главной и уточнения из фактов: доставка, своё производство, сроки, опт.
- Цели Метрики по тому, что нашлось на сайте: форма, клик по `tel:`, клик по `mailto:`, мессенджер.
- Выгрузка CSV для Директ Коммандера. В кабинет по-прежнему ничего не отправляем.

**Готово, когда:** на k-spec отчёт показывает группы с фразами, минус-словами и быстрыми ссылками, CSV открывается в Коммандере без ручной правки колонок. Частот у фраз нет, пока выключен Wordstat; так и подписано.

**Код:** новый `src/lib/briefs/campaign.ts`, тесты рядом; блок на экране; таблица в PDF команде; маршрут выгрузки.

### R.2 — Веб-ссылка для клиента ⚪

Ссылка открывается в мессенджере сразу, нормально выглядит на телефоне и обновляется после повторного разбора. PDF остаётся.

- Публичная страница только для чтения по случайному токену: `/r/<token>`. Токен в `brief_projects`, его можно отозвать.
- Содержимое = клиентская версия PDF: сайт, «Перед запуском рекламы», карта посадочных, SEO, КП, контакты Konversus.
- Кнопки «Скопировать ссылку» и «Отозвать» в отчёте.
- `noindex`, без данных команды, без заметок человека.

**Готово, когда:** ссылка открывается без входа, после отзыва отвечает 404, в HTML нет фактов и гипотез модели.

**Осторожно:** middleware сейчас пускает в `/api/admin/briefs/*` только пользователей Стратега. Публичный маршрут — отдельный путь, не ослаблять существующий доступ.

### R.3 — Конкуренты по адресам ⚪

Человек вводит 1–3 адреса конкурентов. Тот же HTTP-разбор, без платного Search API и без выдачи Яндекса.

- Таблица «у вас / конкурент 1 / 2 / 3»: цены текстом, сроки, гарантии, своё производство, способы связи, форма, Метрика.
- Каждая ячейка — факт со страницы со ссылкой. Нет на странице — «нет данных», а не «нет».
- Блок есть в клиентской версии: это самый убедительный аргумент для клиента.

**Готово, когда:** на k-spec с тремя адресами таблица собирается за один прогон, время разбора растёт не больше чем вдвое.

**Нельзя:** искать конкурентов в выдаче, пока не оплачен Search API.

### R.4 — SEO шире ⚪

- Обход до 30–50 страниц по `sitemap.xml`, с лимитом времени и тем же запретом на приватные адреса.
- Битые ссылки, цепочки переадресаций, страницы без H1, одинаковые title и description, почти пустые страницы.
- Коммерческие факторы Яндекса: реквизиты и ИНН, адрес и карта, отзывы, цены, гарантии, политика конфиденциальности.
- Микроразметка schema.org, Open Graph, переадресация на https, единый вариант адреса с `www` или без.
- Скорость на телефоне через PageSpeed Insights API (бесплатный ключ в `.env`, не в git).
- Выгрузка задач программисту списком с приоритетом «до запуска / позже».

**Готово, когда:** на k-spec отчёт разработчику показывает найденное по всему sitemap, разбор укладывается в 2 минуты, полоса прогресса показывает число страниц.

### R.5 — Потенциал из прогноза Яндекса ⏸️

Включать только после `BRIEFS_WORDSTAT=1` (см. [STRATEG.md](STRATEG.md), раздел Wordstat).

- Фразы из R.1 → Wordstat (частоты) → прогноз бюджета Директа (`CreateNewForecast` / `GetForecast`, API версии 4 Live).
- В отчёте: «по N фразам в регионе Яндекс прогнозирует X показов, цена клика Y–Z ₽», с датой и подписью источника.
- Конверсию сайта вводит человек; строка помечена как допущение. Модель конверсию не придумывает.

**Нужно:** OAuth-токен Директа, отдельное согласование с владельцем аккаунта.

---

### R.6 — Было / стало ⚪

- Повторный разбор сравнивается с прошлым прогоном: что исправили, что сломалось, что появилось.
- Блок в отчёте и строка в клиентской версии: «С прошлого разбора исправлено 4 пункта».

**Готово, когда:** второй прогон k-spec показывает разницу по таблицам проверок.
