# FL.ru — сбор заказов на хабе

Один процесс на хабе для всех партнёров: PM2 `leads-fl` → `src/collectors/fl-poller.ts`.
Аккаунты партнёров не используются: публичная лента `https://www.fl.ru/projects/` обычным HTTP, без браузера.
Откликается партнёр сам, со своего аккаунта FL.

## Как работает

- Опрос раз в 1/3/6 мин (случайно, ±20%), 07:00–23:00 МСК; ночью только heartbeat раз в 10 мин.
- Берутся только карточки типа «Заказ» (вакансии и конкурсы пропускаются).
- Новый заказ → страница проекта (полный текст, `id="projectp<ID>"`) → `saveAndNotify` в каждый включённый источник `platform: "fl"` со своими фильтрами.
- `externalId = fl-<id проекта>-<первые 8 символов sourceId>`: один заказ может уйти нескольким партнёрам.
- Первый запуск (нет `~/.leads-hub/fl/seen.json`) — лента помечается просмотренной, в Telegram ничего.
- CircuitBreaker `~/.leads-hub/fl/circuit-breaker.json`: 3 ошибки за 10 мин → пауза 60 мин.
- Telegram: заголовок `🟦 FL.ru · …`, кнопка «Открыть на FL.ru».

## Сторож

`leads-health` (`watchYouDoAgents`, платформы `youdo` и `fl`): 🔴 нет heartbeat 15+ мин → `pm2 logs leads-fl`; 🟠 лента не читается 20+ мин (блок IP хаба / смена вёрстки).

## Подключить партнёра

Создать `Source { platform: "fl", name: "FL.ru", color: "#2f6fed" }` в его workspace, `config` — фильтры как у Profi
(`titleKeywords`, `titleMinusKeywords`, `keywords`, `minusKeywords`, `showNoBudget: true`, часы). Процесс подхватит его в следующем цикле.
Пауза партнёра — `enabled: false`.

## Риски

Аккаунт партнёра не задействован — блокировать нечего. Худший случай — блок IP хаба на FL: сборщик уходит в паузу, сторож сообщает.
Нагрузка: 1 запрос ленты за цикл + по запросу на каждый новый заказ (~20–60 запросов/час).
